# রেস্টুরেন্ট পস (Restaurant POS) — বাংলা টিউটোরিয়াল ও ব্যবহার নির্দেশিকা

মোবাইল-ফার্স্ট, অফলাইন রেস্টুরেন্ট পয়েন্ট-অফ-সেল (POS) অ্যাপ্লিকেশন। এই ডকুমেন্টে ইনস্টলেশন থেকে শুরু করে দৈনিক বিলিং, ডিউ কালেকশন, রিপোর্ট, দোকান বন্ধ করা এবং ব্যাকআপ—সবকিছু ধাপে ধাপে বাংলায় দেওয়া হয়েছে।

> অ্যাপের ইন্টারফেস ইংরেজিতে, কিন্তু এই নির্দেশিকায় সব পদক্ষেপ বাংলায় বোঝানো হয়েছে। বোতামের নাম ইংরেজিতেই লেখা আছে, যাতে স্ক্রিনে সহজে খুঁজে পান।

## ১. অ্যাপটি কী করে

একটি ডিভাইসে (মোবাইল/ট্যাব/কম্পিউটার) রেস্টুরেন্টের দৈনিক কাজ চালানোর জন্য এটি একটি সম্পূর্ণ লোকাল POS:

- ডাইন-ইন টেবিল ও পার্সেল অর্ডার
- মেনু আইটেম কোড দিয়ে দ্রুত অর্ডার
- কার্টে পরিমাণ বাড়ানো/কমানো, আইটেম মুছে ফেলা
- ফিক্সড ডিসকাউন্ট
- VAT ও সার্ভিস চার্জ
- নগদ পেমেন্ট, ফেরত টাকা হিসাব
- বাকি (Due) বিক্রি ও পরে নগদে আদায়
- ৫৮ মিমি রসিদ প্রিন্ট
- মেনু ও টেবিল ব্যবস্থাপনা
- দৈনিক বিক্রি, খরচ, লাভ-ক্ষতি, টপ আইটেম ও ৭ দিনের চার্ট
- দিন বন্ধ (Day Close) ও ক্যাশ মিলানো
- সম্পূর্ণ ডেটার JSON ব্যাকআপ ও রিস্টোর

সব ডেটা ব্রাউজারের `IndexedDB`-তে থাকে। কোনো ব্যাকএন্ড ডেটাবেস সার্ভার, লগইন বা ইন্টারনেট সংযোগ প্রয়োজন নেই; অ্যাপের ফাইলগুলো লোকালি চালানোর জন্য Vite/dev server ব্যবহৃত হয়। ডেটা শুধু যে ব্রাউজার/ডিভাইসে কাজ করছেন সেখানেই থাকবে।

## ২. জরুরি সীমাবদ্ধতা

শুরুর আগে এই বিষয়গুলো জেনে নিন:

- অ্যাপটি **সিঙ্গেল-ডিভাইস** ব্যবহারের জন্য। একাধিক ফোন/কম্পিউটার একসাথে একই ডেটা দেখবে না।
- বর্তমানে **স্প্লিট পেমেন্ট নেই**। একটি বিল পুরো নগদ অথবা পুরো বাকি—এই দুটোর একটি হিসেবে সম্পন্ন হবে।
- বাকি আদায়ও পুরো টাকা একবারে; আংশিক আদায়ের সুবিধা নেই।
- কার্ড, বিকাশ, নগদ—এগুলোর আলাদা পেমেন্ট বাটন ইন্টারফেসে নেই।
- কিচেন প্রিন্ট/KOT, ইনভেন্টরি, ওয়েটার অ্যাকাউন্ট, মাল্টি-ব্রাঞ্চ—এসব এখন নেই।
- বিলের ডিসকাউন্ট শুধু **ফিক্সড টাকার অঙ্ক** হিসেবে; পার্সেন্ট ডিসকাউন্ট নেই।
- প্রিন্ট হয় ব্রাউজারের প্রিন্ট ডায়ালগ দিয়ে। সরাসরি থার্মাল প্রিন্টার/ESC-POS কমান্ড নেই।
- অ্যাপে লগইন বা পাসওয়ার্ড নেই। ডিভাইসে যার access আছে, সে সব ডেটা দেখতে/বদলাতে পারবে।
- কোনো ক্লাউড সিঙ্ক নেই। ডিভাইস নষ্ট হলে বা ব্রাউজার ডেটা মুছে গেলে ব্যাকআপ ছাড়া ডেটা ফিরে আসবে না।

## ৩. সিস্টেম প্রয়োজন

- **Node.js 22 LTS** (সর্বনিম্ন 20.19+) এবং সাথে npm
- আধুনিক ব্রাউজার: Chrome, Edge, Firefox বা Safari
- মোবাইল ব্যবহারে টাচ-বান্ধব স্ক্রিন (৩৬০px বা বেশি প্রস্থ)
- ডেভেলপমেন্ট/লোকাল সার্ভার চালানোর জন্য কম্পিউটার
- প্রিন্ট করতে ৫৮ মিমি থার্মাল প্রিন্টার (ঐচ্ছিক)

Node.js ইনস্টল আছে কিনা দেখুন:

```powershell
node -v
npm -v
```

সংস্করণ না দেখালে [nodejs.org](https://nodejs.org/) থেকে LTS সংস্করণ ইনস্টল করুন।

## ৪. ইনস্টল ও চালু করা

### ৪.১ প্রজেক্ট ফোল্ডারে যান

```powershell
cd F:\RestaurantManagement
```

### ৪.২ ডিপেন্ডেন্সি ইনস্টল

```powershell
npm install
```

### ৪.৩ ডেভেলপমেন্ট সার্ভার চালু

```powershell
npm run dev
```

টার্মিনালে সাধারণত এই ধরনের ঠিকানা দেখাবে:

```text
Local:   http://localhost:5173/
```

ব্রাউজারে `http://localhost:5173/` খুলুন।

### ৪.৪ মোবাইল/একই Wi-Fi-এর অন্য ডিভাইস থেকে খোলা

কম্পিউটারে চালান:

```powershell
npm run dev -- --host
```

Vite যে `Network:` ঠিকানা দেখাবে, যেমন `http://192.168.0.10:5173/`, সেটি একই Wi-Fi-এর ফোনে খুলুন। Windows Firewall জিজ্ঞেস করলে Node.js-কে allow করুন।

> মনে রাখবেন: মোবাইলে যে ডেটা তৈরি হবে তা মোবাইলের ব্রাউজারে থাকবে, কম্পিউটারের ডেটা নয়। ডেটা এক ডিভাইস থেকে আরেকটিতে নিতে চাইলে Settings → Backup & restore দিয়ে export করে অন্য ডিভাইসে import করতে হবে।

### ৪.৫ প্রোডাকশন বিল্ড

```powershell
npm run build
```

বিল্ড শেষে `dist/` ফোল্ডার তৈরি হবে। লোকালি দেখতে:

```powershell
npm run preview
```

`dist/` যেকোনো স্ট্যাটিক হোস্টিং-এ দেওয়া যায়। তবে SPA রাউটিং-এর জন্য server-side fallback (সব রুট `index.html`-এ) কনফিগার করতে হবে। হোস্ট/ডোমেইন/পোর্ট বদলালে আগের IndexedDB ডেটা আলাদা হয়ে যাবে—আগে ব্যাকআপ নিন।

### ৪.৬ টেস্ট ও কোয়ালিটি চেক

```powershell
npm test
npm run lint
npm run build
npm run typecheck
```

## ৫. প্রথমবার সেটআপ

প্রথমবার অ্যাপ খুললে ডেমো ডেটা স্বয়ংক্রিয়ভাবে তৈরি হয়:

- ১২টি টেবিল: `T-01` থেকে `T-12`
- ২৬টি মেনু আইটেম
- ডিফল্ট সেটিংস: `Demo Restaurant`, VAT 0%, Service 0%, রাউন্ডিং চালু

এগুলো বদলে নিজের রেস্টুরেন্টের তথ্য দিন।

### ৫.১ রেস্টুরেন্টের তথ্য সেট করুন

1. নিচের ট্যাব থেকে **Settings** খুলুন।
2. **Restaurant profile** অংশে দিন:
   - `Restaurant name` — রেস্টুরেন্টের নাম (আবশ্যক)
   - `Phone` — ফোন নম্বর
   - `Address` — ঠিকানা
   - `Receipt footer` — রসিদের নিচের বার্তা
3. **Charges** অংশে দিন:
   - `VAT (%)` — ০ থেকে ১০০
   - `Service (%)` — ০ থেকে ১০০
   - `Round total to taka` — চালু থাকলে বিল নিকটতম পূর্ণ টাকায় রাউন্ড হবে
4. **Save changes** চাপুন।
5. সবুজ **Settings saved.** বার্তা দেখলে সেটিংস সংরক্ষিত হয়েছে।

VAT ও সার্ভিস চার্জ ডিসকাউন্টের পরের অঙ্কের ওপর হিসাব হয়। সেটিংস বদলালে আগের Paid বিলের সংরক্ষিত অঙ্ক বদলায় না; নতুন বিল এবং চলমান unpaid বিলের পরবর্তী হিসাবে নতুন সেটিংস প্রযোজ্য হয়।

### ৫.২ মেনু যাচাই/পরিবর্তন

**Menu** ট্যাবে গিয়ে নিজের আইটেম যোগ, সম্পাদনা বা নিষ্ক্রিয় করুন। বিস্তারিত [মেনু ম্যানেজমেন্ট](#৮-মেনু-ম্যানেজমেন্ট) অংশে।

### ৫.৩ টেবিল যাচাই/পরিবর্তন

**Settings → Dining tables**-এ গিয়ে টেবিল যোগ/নাম বদল/মুছুন। বিস্তারিত [টেবিল ম্যানেজমেন্ট](#৯-টেবিল-ম্যানেজমেন্ট) অংশে।

### ৫.৪ প্রথম ব্যাকআপ নিন

সেটআপ শেষে **Settings → Backup & restore → Export backup** চেপে একটি JSON ফাইল নামিয়ে নিরাপদ জায়গায় রাখুন। এতে করে ভুল করে ডেটা মুছে গেলেও ফিরিয়ে আনা যাবে।

### প্রথম দিনের চেকলিস্ট

- [ ] রেস্টুরেন্টের নাম, ফোন, ঠিকানা, রসিদ ফুটার
- [ ] VAT ও সার্ভিস চার্জ
- [ ] মেনু আইটেম ও দাম/খরচ
- [ ] টেবিলের নাম ও সিট সংখ্যা
- [ ] একটি টেস্ট অর্ডার করে দেখা
- [ ] প্রথম ব্যাকআপ

## ৬. স্ক্রিন ও নেভিগেশন

নিচের ট্যাববার দিয়ে প্রধান স্ক্রিনে যাওয়া যায়:

| ট্যাব | কাজ |
|---|---|
| **Tables** | টেবিল, পার্সেল, চলমান অর্ডার, unpaid মোট |
| **Menu** | মেনু আইটেম যোগ/সম্পাদনা/সক্রিয়-নিষ্ক্রিয় |
| **Orders** | Unpaid, Due, Paid অর্ডারের তালিকা |
| **Reports** | দৈনিক বিক্রি, লাভ-ক্ষতি, খরচ, দিন বন্ধ |
| **Settings** | রেস্টুরেন্ট তথ্য, টেবিল সেটআপ, ব্যাকআপ |

অর্ডার স্ক্রিন ও রসিদ স্ক্রিনে ট্যাববার লুকানো থাকে; ফিরতে **Back** ব্যবহার করুন।

## ৭. প্রথম অর্ডার: শুরু থেকে রসিদ পর্যন্ত

### ধাপ ১: টেবিল খুলুন

1. **Tables** ট্যাবে যান।
2. সবুজ টেবিল মানে খালি, হলুদ টেবিল মানে চলমান unpaid অর্ডার আছে।
3. `T-01`-এর মতো টেবিলে ট্যাপ করুন।
4. **Start new order** চাপুন।
5. অর্ডার স্ক্রিন খুলবে। টেবিলে আগে থেকেই অর্ডার থাকলে **Open order** দেখাবে।

উপরের কার্ডে **Unpaid total** ও কতটি টেবিল খালি আছে দেখা যায়।

### ধাপ ২: আইটেম যোগ করুন

তিনভাবে যোগ করা যায়:

**ক) মেনু কার্ডে ট্যাপ**

ক্যাটাগরি বেছে নিন, তারপর আইটেম কার্ডে ট্যাপ করুন। প্রতিবার ট্যাপে একটি করে পরিমাণ বাড়বে।

**খ) সার্চ**

`Search name or code`-এ নাম বা কোড লিখে আইটেম খুঁজুন, তারপর কার্ডে ট্যাপ করুন।

**গ) Quick add কোড**

`Quick add: 201 201*2` ইনপুটে কোড লিখে **Add** চাপুন।

উদাহরণ:

| ইনপুট | অর্থ |
|---|---|
| `201` | কোড ২০১-এর ১টি |
| `201 501` | ২০১-এর ১টি + ৫০১-এর ১টি |
| `201*2` | ২০১-এর ২টি |
| `201x2` | ২০১-এর ২টি |
| `201*2, 501x3` | ২০১-এর ২টি + ৫০১-এর ৩টি |

নিয়ম:

- কোড ও পরিমাণের মাঝে `*`, `x` বা `X` ব্যবহার করুন।
- একাধিক কোড স্পেস বা কমা দিয়ে আলাদা করুন।
- মেনু কোড case-sensitive।
- Quick add-এ ব্যবহার করতে চাইলে কোডে শুধু অক্ষর, সংখ্যা, `-` ও `_` রাখুন।
- অজানা বা ভুল কোড হলে অর্ডারে কিছু যোগ হবে না; লাল বার্তা দেখাবে।

### ধাপ ৩: কার্ট পর্যালোচনা

নিচের সবুজ **Review** বারে ট্যাপ করুন। **Current order** শিটে:

- `+` / `−` দিয়ে পরিমাণ বদলান
- একধিক হলে `−` চাপলে পরিমাণ কমে; ১ থেকে কমালে আইটেম মুছে যায়
- ট্র্যাশ আইকনে ট্যাপ করে আইটেম মুছুন
- **Review bill** চাপলে বিল শিট খুলবে

### ধাপ ৪: বিল ও পেমেন্ট

Bill শিটে দেখা যাবে:

- Subtotal
- VAT (সেটিংস অনুযায়ী)
- Service (সেটিংস অনুযায়ী)
- Total
- Discount (ফিক্সড টাকা)
- Cash received ও Change

**ডিসকাউন্ট দিতে:**

1. `Discount (৳)`-এ টাকার অঙ্ক লিখুন।
2. VAT/সার্ভিস নতুন অঙ্কের ওপর হিসাব হবে।
3. ডিসকাউন্ট সাবটোটালের বেশি হলে সাবটোটাল পর্যন্ত ধরা হবে।

**নগদ পেমেন্ট:**

1. `Cash received (৳)`-এ গ্রাহক কত টাকা দিয়েছেন লিখুন।
2. চাইলে প্রস্তাবিত টাকার বাটনে ট্যাপ করুন।
3. `Change` দেখে ফেরত টাকা মিলিয়ে নিন।
4. নগদ কম দিলে **Short by** দেখাবে এবং বিল সম্পন্ন হবে না।
5. **Mark paid · ৳...** চাপুন।

**বাকি (Due) পেমেন্ট:**

1. উপরে **Due** বাটন বেছে নিন।
2. চাইলে `Customer name` ও `Phone` দিন।
3. `Note` দিতে পারেন।
4. **Mark as due · ৳...** চাপুন।
5. টেবিল খালি হয়ে যাবে, অর্ডার **Orders → Due**-তে যাবে।

### ধাপ ৫: রসিদ

পেমেন্ট শেষ হলে রসিদ স্ক্রিন খুলবে:

- রেস্টুরেন্টের নাম, ঠিকানা, ফোন
- অর্ডার নম্বর, তারিখ, টেবিল/পার্সেল
- আইটেম ও পরিমাণ
- Subtotal, ডিসকাউন্ট, VAT, Service, Total
- পেমেন্ট পদ্ধতি, নগদ গ্রহণ ও ফেরত
- রেসিদ ফুটার

বাটন:

- **Print receipt** — ব্রাউজার প্রিন্ট ডায়ালগ
- **New order** — নতুন **পার্সেল** অর্ডার শুরু করে
- **Tables** — টেবিল স্ক্রিনে ফিরে যায়

> dine-in নতুন অর্ডার চাইলে রসিদ থেকে নয়, Tables স্ক্রিনে টেবিল বেছে নিন।

## ৮. মেনু ম্যানেজমেন্ট

**Menu** ট্যাবে:

### নতুন আইটেম

1. উপরে **Add** চাপুন।
2. দিন:
   - `Code` — ইউনিক কোড (যেমন `201`)
   - `Name` — আইটেমের নাম
   - `Price (৳)` — বিক্রয়মূল্য
   - `Cost (৳)` — ক্রয়/উৎপাদন খরচ (লাভ হিসাবে লাগবে)
   - `Category`
   - `Available` — চালু/বন্ধ
3. **Save item**।

### সম্পাদনা

আইটেমের নাম/দামের অংশে ট্যাপ করুন, তথ্য বদলে **Save item** চাপুন।

### সক্রিয়/নিষ্ক্রিয়

 `Available` টগল বন্ধ করলে আইটেম নতুন অর্ডারের মেনুতে দেখাবে না। পুরোনো অর্ডার/রসিদ অপরিবর্তিত থাকবে।

### মুছে ফেলা

আইটেম সম্পাদনা করে **Delete item** → **Delete**।

- মেনু থেকে মুছে গেলেও পুরোনো অর্ডারে আইটেমের নাম, দাম ও খরচ সংরক্ষিত থাকে।
- কোড ইউনিক; একই কোড অন্য আইটেমে দিলে লাল বার্তা আসবে।
- দাম/খরচ বদলালে নতুন অর্ডারে নতুন দাম লাগবে; চলমান অর্ডারের পুরোনো লাইন আগের দামই রাখবে।

### টেবিল সম্পাদনা

টেবিলে ট্যাপ → **Delete table** → **Delete**।

## ১০. ডিউ (বাকি) ও অর্ডার তালিকা

**Orders** ট্যাবে তিনটি ট্যাব:

- **Unpaid** — চলমান অর্ডার; **Open order** বা **Cancel**
- **Due** — বাকি অর্ডার; **Collect cash** বা **Receipt**
- **Paid** — সম্পন্ন অর্ডার; **Receipt**

### বাকি আদায়

1. **Orders → Due**-তে যান।
2. অর্ডারের **Collect cash** চাপুন।
3. নিশ্চিতকরণে **Collect cash** চাপুন।
4. পুরো বিলের টাকা নগদ হিসেবে আদায় হবে এবং রসিদ খুলবে।

বাকি আদায়ের পর অর্ডার **Paid**-এ চলে যাবে। আংশিক আদায় করা যাবে না।

### অর্ডার বাতিল (Void)

- Unpaid অর্ডার **Cancel** করে কারণ লিখে বাতিল করা যায়।
- বাতিল অর্ডার টেবিল খালি করে দেয়।
- Void অর্ডার Unpaid/Due/Paid তালিকায় দেখায় না; অডিট লগে সংরক্ষিত থাকে।

### Clear vs Cancel

- **Clear all items** — অর্ডারের সব আইটেম মুছে দেয়, টেবিল খোলা থাকে।
- **Cancel order** — পুরো অর্ডার void করে টেবিল খালি করে।

খালি unpaid ড্রাফট ছেড়ে গেলে টেবিল স্ক্রিনে ফিরলে সেটি পরিষ্কার হয়ে যায়।

## ১১. রিপোর্ট, খরচ ও দিন বন্ধ

**Reports** ট্যাবে উপরে তারিখ বদলানো যায়:

- বাম/ডান তীর দিয়ে আগের/পরের দিন
- তারিখে ট্যাপ করে ক্যালেন্ডার
- ভবিষ্যতের তারিখ নির্বাচন করা যায় না

### রিপোর্টের হিসাব

| নাম | অর্থ |
|---|---|
| Sales collected | নির্বাচিত দিনে আদায় হওয়া বিলের মোট (paidAt অনুযায়ী) |
| Due collected | আগের দিনের বিল হলেও আজ আদায় হওয়া বাকির অংশ |
| Gross sales | আইটেমের সাবটোটাল |
| Discounts | দেওয়া ফিক্সড ডিসকাউন্ট |
| Net sales | Gross sales − Discounts |
| VAT / Service | বিলে সংগৃহীত VAT ও সার্ভিস চার্জ |
| Total collected | Net sales + VAT + Service (রাউন্ডিং সহ) |
| Cost of goods | আইটেমের unit cost × পরিমাণ |
| Gross profit | Net sales − Cost of goods |
| Expenses | নির্বাচিত দিনের খরচ |
| Net profit | Gross profit − Expenses |
| Due outstanding | সব সময়ের বাকি (দিন-নির্দিষ্ট নয়) |
| Items sold | বিক্রি হওয়া মোট ইউনিট |

- **Last 7 days** চার্ট নির্বাচিত তারিখ শেষ করে আগের ৭ দিন দেখায়।
- **Top items** পরিমাণ অনুযায়ী সেরা ৫টি আইটেম।
- VAT/Service গ্রাহকের কাছ থেকে সংগৃহীত হলেও লাভের হিসাবে ব্যবসার আয় হিসেবে ধরা হয় না; Net profit হিসাবে শুধু net sales ও cost/expense ধরা হয়।

### খরচ যোগ

1. Reports-এ **Expenses** সেকশনে **Add**।
2. ক্যাটাগরি বেছে নিন: `Ingredients`, `Utilities`, `Salary`, `Rent`, `Transport`, `Other`
3. টাকা ও ঐচ্ছিক নোট দিন।
4. **Add expense**।

খরচ ডিলিট করতে পাশের ট্র্যাশ আইকন → **Delete**। খরচ সেই দিনের net profit কমায়।

### দিন বন্ধ (Day Close)

দিনের শেষে:

1. Reports-এ সঠিক তারিখ বেছে নিন।
2. **Day close** সেকশনে **Close day** চাপুন।
3. `Opening cash` — ড্রয়ারের শুরুর টাকা; নির্বাচিত তারিখের আগের সর্বশেষ day-close-এর counted cash ডিফল্টভাবে বসে (না থাকলে ০), দরকারে বদলান।
4. `Counted cash` — ড্রয়ারে বাস্তবে গুনে পাওয়া টাকা।
5. সিস্টেম দেখাবে:
   - Expected cash = Opening cash + Collected sales − Expenses
   - Difference = Counted cash − Expected cash
6. নোট লিখে **Save day close**।

দিন বন্ধের পর **Update day close** দিয়ে আবার সংশোধন করা যায়।

- রিস্টোর একটিমাত্র ডেটাবেস ট্রানজেকশনে হয়; ব্যর্থ হলে পুরোনো ডেটাই থাকে।

### কখন ব্যাকআপ নেবেন

- প্রতিদিন দোকান বন্ধ করার সময়

4. Margin সর্বনিম্ন রাখুন; scale 100%।
5. প্রয়োজনে browser-এর header/footer বন্ধ করুন।

অ্যাপের print CSS রসিদকে ৫৮ মিমি প্রস্থ ও ৪ মিমি পেজ মার্জিনে সাজায়। প্রিন্টারে কাগজ কাটা পড়লে প্রিন্টার ড্রাইভারের paper width ঠিক করুন। এটি ব্রাউজার প্রিন্ট, তাই প্রিন্টারভেদে সামান্য পার্থক্য হতে পারে।

## ১৪. ডেটা কোথায় থাকে ও নিরাপত্তা

- ডেটা থাকে ব্রাউজারের **IndexedDB** ডেটাবেসে, নাম `restaurant-pos`।
- কোনো ডেটা সার্ভারে যায় না।
- একই ব্রাউজারের একই origin (protocol + host + port) হলেই ডেটা দেখা যায়।
  - `http://localhost:5173` এবং `http://127.0.0.1:5173` আলাদা storage
  - পোর্ট বদলালে (যেমন 5173 → 5199) ডেটা আলাদা দেখাবে
- ইনকগনিতো/প্রাইভেট উইন্ডো বন্ধ করলে ডেটা মুছে যেতে পারে।
- ব্রাউজারের "Clear site data"/"Clear browsing data" দিলে POS ডেটাও মুছে যাবে।
- ব্যাকআপ ফাইল নিজে থেকে কোথাও আপলোড হয় না; যেখানে রাখবেন সেখানেই থাকবে।
- ডেটা এনক্রিপ্টেড নয় এবং অ্যাপে লগইন নেই; ডিভাইসের physical নিরাপত্তা নিশ্চিত করুন।

### ডেমো ডেটা রিসেট (সতর্কভাবে)

সব ডেটা মুছে আবার প্রথমবারের ডেমো সেটআপ চাইলে:

1. অন্য সব POS ট্যাব বন্ধ করুন।
2. ব্রাউজারে DevTools → **Application** → **Storage** → **IndexedDB** → `restaurant-pos` ডিলিট করুন।
3. পেজ রিলোড করুন।

অথবা DevTools Console-এ:

```js
const request = indexedDB.deleteDatabase('restaurant-pos');
request.onsuccess = () => location.reload();
request.onerror = () => alert('ডেটাবেস ডিলিট করা যায়নি');
```

এটি সব অর্ডার, মেনু, টেবিল, খরচ ও সেটিংস মুছে ফেলবে। আগে ব্যাকআপ নিন।

### বিলের সূত্র

```text
subtotal = Σ (unit price × qty)
discount = min(fixed discount, subtotal)
taxable  = subtotal − discount
vat      = taxable × vat% / 100
service  = taxable × service% / 100
total    = round(taxable + vat + service)   // rounding চালু থাকলে
cogs     = Σ (unit cost × qty)
gross profit = net sales − cogs
net profit   = gross profit − expenses
```
